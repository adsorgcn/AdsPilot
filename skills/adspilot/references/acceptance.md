# User-agent acceptance

Use this only when the owner asks to evaluate AdsPilot. Start without external
side effects. Loading a Skill, reading a synthetic fixture, or passing a check
does not authorize real campaign creation or conversion upload.

## 1. Inspect this host

Read the Skill and I-Lang profile. Discover actual host tools and their schemas,
then map only the requested operations using [host binding](host.md) and the
[operation registry](../contracts/operations.json). Report a compact table:
task, available capability, missing evidence, what the AI can do now, and the
smallest remaining owner/host action. Do not infer permission from tool presence.
Keep consent links and credential submission inside the host's native flow.

## 2. Run an explicitly simulated rehearsal

Use owner-supplied samples or clearly synthetic records, never a hidden live
account. Include these material cases and show the resulting plan or receipt:

- Existing connection: product, Japan, JPY 5,000/day, new campaign paused;
  connector owns the API app, user consent pending. Discover/fill known facts.
- Permission difference: reporting succeeds; keyword planning returns a
  structured authorization/configuration error. Inspect exact evidence and
  capability restrictions; keep unavailable volume unknown, not zero.
- Interrupted create: an exact approved paused plan was submitted, then timed
  out without resource IDs. Reload the operation record and propose correlated
  read-only reconciliation. The error message is not new spending authority.
- Changed account: yesterday's plan/approval was USD/New York; today's selected
  customer is JPY/Tokyo. Resolve only the missing business decisions and create
  a new exact plan, without transferring account-specific approval.
- Commission corrections: one original transaction plus a distinct negative
  correction, repeated on a later overlapping page; an unrelated tracking token
  is unmatched. Compute exact totals, preserve deltas and incomplete windows,
  isolate unmapped conversion candidates, and do not upload during import.
- Conversion lifecycle: a new integration has no evidence of legacy Ads upload
  eligibility; a Data Manager request returns a request ID but no destination
  diagnostics. Keep supported route and accepted/pending versus confirmed
  separate. Do not claim attribution or repeat an uncertain upload.

Report source mode and evidence limits in every case. These are simulated
behavior checks, not proof of real connectivity, statistical reliability, or
host enforcement. Any discrepancy should be a reproducible failure report with
redacted input, actual result, expected task outcome and next repair check.

## 3. Evaluate real capabilities separately

Only if requested and already authorized, inspect identity, target customer,
currency/timezone, campaign reads and keyword planning independently. Never
turn a read-only acceptance request into a write test. Use the requested date
range and preserve pagination, missing metrics, source/version and request IDs.

For a separately requested paused-campaign acceptance, prepare the complete
plan, run actual provider validation, resolve missing scope, obtain the host's
durable claim, submit once and compare every resource with the plan. Follow
[Google workflow](google-ads.md) and [records](records.md). Do not enable a
paused campaign or remove it as automatic test cleanup; cleanup is a separate
account mutation requiring authorization.

For a separately authorized affiliate integration, verify official CJ schema,
publisher/property, current program terms and network-issued links. Start with
export reconciliation. Before any conversion upload, verify source rights,
action owner, value semantics, current route and per-item/async diagnostics as
specified in [affiliate workflow](affiliate.md). Rehearsal results are not
substitutes for those provider observations.

Return one acceptance receipt: version, host/schema evidence, each requested
case, actual state, verified outputs, failures, owner/host/provider actions and
resume checkpoint. Do not mark every installation ready from one success.
