# 使用方法：无人值守日常循环

::STATE{@PART, name:loop, kind:core, external_apis:none, entry:core/loop/daily.py}
::OBJECTIVE{id:loop|owner:user|trust:untrusted|version:1|status:active}
  target: 每天定时跑一轮，人不在也能跑，跑完有账、有本轮报告、有退出码
  ACCEPT: 调度器装好 AND 连续 7 天每天一条 runs 记录 AND 其中没有 exit_code 为 1 或 3 AND needs_human 只出现在证件、付款、申诉三处
  NON_GOALS: 交互式问人；在循环里改 SOUL 或改 f_v5

## 一轮做什么

```
[RUN:@SELFCHECK|quick]=>[PULL:@MAPPINGS]=>[PULL:@TRAFFIC_REPORT]=>[PULL:@COMMISSIONS]=>[RECONCILE]
  =>[JUDGE:anomaly.escalate]=>[JUDGE:campaign.adjust|each]=>[JUDGE:keyword.action|each]=>[JUDGE:conversion.upload]
  =>[EXECUTE|M1_M2_only]=>[REPORT]=>[LEDGER:runs]=>[Ω]
```

每步都幂等：同一天跑两次，账本不会重复，报告只是覆盖。默认 dry-run；`config.apply` 为 true 或命令带 `--apply` 才对外部写。

## 步骤

[STEP:1|先手动跑一轮|by:agent]

```bash
python3 core/loop/daily.py --dry-run
cat runs/<run_id>/run.log
cat runs/<run_id>/report.json
```

退出码：0 正常；2 需要本人（看 report.needs_human）；3 自检或外部步骤失败；4 没有 config。

[STEP:2|装调度器|by:agent]
Linux 用 systemd timer（推荐）：

```bash
sed "s#__ROOT__#$(pwd)#g" core/loop/systemd/adspilot-daily.service | sudo tee /etc/systemd/system/adspilot-daily.service >/dev/null
sudo cp core/loop/systemd/adspilot-daily.timer /etc/systemd/system/
sudo systemctl daemon-reload && sudo systemctl enable --now adspilot-daily.timer
systemctl list-timers adspilot-daily.timer
```

没有 systemd 用 cron：`crontab -e` 加一行，照 `core/loop/crontab.example`。macOS 用 launchd，Windows 用任务计划，命令都是同一条 `python3 core/loop/daily.py`。

环境变量（凭据）放在调度器读得到的地方：systemd 用 `EnvironmentFile=/etc/adspilot.env`（权限 600），cron 在 crontab 顶部写。仓库里不放。

[STEP:3|manual 路每天两件事|by:agent]
流量插件走 manual 路时，Agent 每天在循环前后做：把关键字报表导出到 `data/inbox/`；把 `runs/<id>/actions-todo.json` 里的动作在后台做掉，然后 `python3 core/loop/daily.py --ack <run_id>`。api 路补齐后这两件事消失。

[STEP:4|哨兵|by:agent]
`runs/` 里最新一条 `run.log` 超过 26 小时没更新，或最近一次退出码是 1 或 3，就是要看的信号。用 `core/loop/sentinel.sh` 接到调度器每小时跑一次，它只查不动，异常时把原因写进 `runs/sentinel.log`，退出码 2。

## 用户说了就照做

用户对某个系列或词明确说过怎么办（比如「这条先别停」「这条预算别加」），Agent 写进 `data/inbox/user-decisions.json`：

```json
{"decisions": [{"node": "campaign.adjust", "target": "AP Roborock Guide", "choice": "keep", "created": "2026-09-26", "until": "2026-10-31", "note": "老板说先别停"}]}
```

字段：`node`、`target`、`choice`、`created`（写这条的那天）、`until`（用户说了期限就填，没说不填，默认 7 天）、`note`。

之后每一轮循环遇到这个节点加这个目标，照用户的做，判断照算，意见记进账本与 `report.json` 的 `judgments[].advice`。

用户回答的是说话那一刻的情况。情况变了，这条决定就失效，这个节点交回判断，和没有用户决定时完全一样：

* 过了 `until`；没写 `until` 时是 `created` 加 SOUL 的 `user_decision.default_days`（默认 7 天）。
* `campaign.adjust`：这条系列从循环第一次看到这条决定起，又多花了 SOUL 的 `user_decision.max_extra_spend`（默认 100 美元，按 `config.fx` 折成账户币种，港币账户约 780 港币）。
* `campaign.adjust`：这条系列的总消耗越过了 `stop_loss.test_spend_total`。

花钱节点（`campaign.adjust`、`keyword.action`，见 SOUL 的 `user_decision.no_wildcard_nodes`）不接受 `target: "*"`，要逐条写目标；写了 `*` 的那条会被忽略。别的节点照旧可以用 `*` 表示整个节点。

Agent 写这条时，当场跟用户复述边界：

```
「这条到 <until> 为止；这条系列如果从现在起再花 <max_extra_spend 折算> 或越过测试总额，我会重新问你」
```

每轮用到了哪些、哪些失效、哪些被忽略，写在 `report.json` 的 `user_decisions`（`applied`、`expired`、`ignored`，后两者带 `why`）；失效或忽略的每条在 `run.log` 里也有一行 `user_decision <node> <target> <choice> expired|ignored <why>`。失效与忽略不新增 needs_human，不改退出码。

::RULE{用户说过的⇒循环照做 不劝不改 判断只记建议}
::RULE{到期 多花出max_extra_spend 越过test_spend_total⇒这条失效 交回判断}
::RULE{花钱节点target写*⇒忽略 写进report.user_decisions.ignored}
::RULE{user-decisions.json只读 循环不回写这个文件 第一次看到的日子与当时的花费只记在ledger的user_decision_anchor}

## 人在哪三处

::RULE{证件与KYC⇒本人|付款与绑卡⇒本人|平台要求本人申诉⇒本人|其余⇒循环自己做}
::RULE{needs_human出现在三处之外⇒这是要修的缺陷 记进CHANGELOG不是记进流程}
