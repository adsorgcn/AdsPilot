# 使用方法：开局（三把钥匙进，一条真系列出）

::STATE{@CORE, part:launch, input:"三把钥匙", output:"自有域名上的落地页 + 一条系列 + 账本里第一条映射", human_steps:0}
::OBJECTIVE{id:launch|owner:user|trust:untrusted|version:1|status:active}
  target: 接入之后跑的第一件事。跑完，Google Ads 里有一条系列指向自己域名上的页，页上的 CTA 经 /go 出站到联盟链接，点击映射进本地账本，日常循环从此接管
  ACCEPT: verify 步三段全通（页面 200、/go 302 带 sid、/export 里的 token 进账本且 gclid 对得上）AND campaign 步建出 campaign_id
  NON_GOALS: 选品判断的对错（那是 SOUL 的事，跑起来再校）、放大、多号

## 前提：三把钥匙已在环境变量里

Cloudflare（`CF_EMAIL` + `CF_GLOBAL_API_KEY`，或 `CF_API_TOKEN`）、Google Ads（`GOOGLE_ADS_*`，见 `plugins/traffic/google-ads/使用方法.md`）、CJ（`CJ_ACCESS_TOKEN` `CJ_PUBLISHER_ID` `CJ_WEBSITE_ID`）。域名在 Cloudflare 账号里。除此之外本人不需要做任何事。

::RULE{开局里出现任何by:human步骤⇒这是要修的缺陷 不是流程}

## 用户说了就照做

每一步的判断都是建议。用户明确说了，Agent 就把用户的话传进去照做，判断照算，放在输出的 `judge.advice` 里，账与警告一并给出：offer 用 `--pick <offer_ref>`，页面用 `--user publish`，建系列用 `--user go`，跳过真点直接启用用 `go --user go`。用户没说，Agent 按判断走，判断不放行就停在那一步，把建议与数字交给用户。

::RULE{用户明确说了⇒传--pick或--user 照做 不劝第二遍}

## 七步（Agent 做，按顺序，每步幂等）

[STEP:1|deploy 建落地位|by:agent]

```bash
python3 core/launch/launch.py deploy --host reviews.example.com --site-name "Widget Reviews" --contact you@example.com --apply
```

主机名选一个新子域名。建好 KV、Worker、域名、隐私与条款页，状态写 `runs/launch/launch.json`。

[STEP:2|offers 拉 offer 选一个|by:agent]

```bash
python3 core/launch/launch.py offers [--top 10]
```

从联盟拉全部已加入的 offer 连点击链接，取 EPC 靠前的 N 家，每家用商家名加网址去关键词插件查词，然后按 SOUL 的 `offer.select` 判。第一条是账：**有一个词的出价小于每次点击赚的钱，这家才能投**。每次点击赚的钱是 EPC÷100（联盟的 EPC 是每百次点击），默认取 7 天与 3 个月里小的那个，按 `config.fx` 换成广告账户币种；词的出价默认用首页出价低位；品牌词只在联盟许竞价品牌词时才算。输出 `economics` 每家一行：每次点击赚多少、最便宜的词多少、几个词过线。

账过了，再看 PPC 政策。联盟 API 不给这个字段，所以默认 SOUL 下第一次多半停在这：把账与建议交给用户定，用户定了就 `--pick <offer_ref>` 照做（账没过、政策没核也照做，警告写在 `picked.warnings`）；用户交给 Agent 定，Agent 就在联盟后台读过线那几家的 Program Terms，写进 `data/inbox/cj-offer-policy.json` 再跑，由判断选。选中的 offer 连同能投的词写进状态，建系列时用。

::RULE{Program_Terms写明不许PPC或不许品牌词⇒不选 换下一个}

[STEP:3|page 写页发页|by:agent]

Agent 按 `core/lp/使用方法.md` 的要求写一页真内容：一个 JSON，键是模板占位符（`tests/fixtures/lp-content.example.json` 是样子），至少 300 词，是给搜这个词的人看的评测或指南，不是广告文案的重复。然后：

```bash
python3 core/launch/launch.py page --content site/widget-x.content.json --slug widget-x-review --apply
```

填模板、`lp_check`、判 `lp.publish`，判断放行或用户 `--user publish` 就推到落地位，连 offer 表一起推。页面 URL 写进状态。

[STEP:4|campaign 建系列|by:agent]

Agent 写 brief（`tests/fixtures/brief.example.json` 是样子：关键词、标题、描述、否定词、国家、预算与出价；`final_url` 与 `offer_ref` 不填就用状态里的）。然后：

```bash
python3 core/launch/launch.py campaign --brief site/widget-x.brief.json --apply
```

生成 spec、逐条核硬限、判 `campaign.launch`，判断放行或用户 `--user go` 就建（超出上限的项写在 `problems` 里当建议）。建好即暂停，campaign_id 写进状态。

[STEP:5|verify 真点一次|by:agent]

```bash
python3 core/launch/launch.py verify
```

用测试 gclid 走一遍：页面 → /go → 302 带 sid → /export → `subid.py pull` → 账本里查到这个 token 且 gclid 对得上。这是整条链第一次在真实世界闭合。

[STEP:6|go 启用|by:agent]

```bash
python3 core/launch/launch.py go --apply
```

系列置 ENABLED。然后按 `core/loop/使用方法.md` 装调度器，日常循环接管。

[STEP:7|status 看到哪了|by:agent]

```bash
python3 core/launch/launch.py status
```

随时看六步哪步做了、下一步是什么。测试收尾用 `teardown --apply`（删系列）或 `teardown --all --apply`（连落地位一起拆）。
