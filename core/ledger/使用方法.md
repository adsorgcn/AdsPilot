# 使用方法：sub-id 归因与对账

::STATE{@PART, name:ledger, kind:core, external_apis:none, db:"<data_dir>/ledger.db (SQLite)"}
::OBJECTIVE{id:ledger|owner:user|trust:untrusted|version:1|status:active}
  target: 每一次点击有 token，每一笔佣金能 join 回 gclid 与关键词，每一笔转化能灌回平台，每一笔拒付能反标
  ACCEPT: 映射表有行 AND 对账 matched 大于 0 AND 转化上传文件生成 AND 拒付生成调整行
  NON_GOALS: 猜 gclid、伪造时间、把没对上的佣金硬塞成转化

## 不变的核心

一个 token 进联盟 sub-id，其余全在本地映射表。token 32 位内纯字母数字（本仓库 20 位，字母表去掉 0 O 1 I），哪家联盟都装得下：CJ `sid`、Impact `subId1`、Awin `clickref`、Rakuten `u1`、ShareASale `afftrack`。映射表：`token → gclid, campaign, adgroup, keyword, page, ts, network, offer`。

## 三种注入形态

默认 **落地页加第一方标签**（合规，per-click）：广告到自己的落地页，页面标签把 gclid 与 ValueTrack 维度挂到本站 `/go`，中转铸 token 存映射再 302 到联盟链接。
退路 **ValueTrack 维度级**（零基建，非 per-click）：sub-id 直接用 `{campaignid}-{adgroupid}`，只能到维度级，拿不到 gclid，灌不回转化。
不用 **直链加跳转注入**：没有落地页直投商家深链，有被判 cloaking 的风险。

## 步骤

[STEP:1|映射入账|by:agent]
中转在线时主干每轮自动 `pull`；手工形态用 `record` 或 `import`：

```bash
python3 core/ledger/subid.py pull --url https://go.example.com/export --key-env ADSPILOT_EXPORT_KEY
python3 core/ledger/subid.py import data/inbox/mappings.jsonl
python3 core/ledger/subid.py stats
```

[STEP:2|对账|by:agent]
联盟插件拉回标准佣金明细后：

```bash
python3 core/ledger/reconcile.py --commissions runs/<id>/commissions.json --out runs/<id>/conversions.json --window-days 90
```

输出五桶：`rows` 能灌回的转化；`chargebacks` 拒付与纠正；`unmatched` sub-id 对不上映射；`out_of_window` 超过 90 天；`invalid` 转化早于点击或 gclid 缺失。只有 `rows` 与 `chargebacks` 进平台，其余进报告。

[STEP:3|灌回|by:agent]
流量插件 `convert` 动作把 `conversions.json` 变成平台上传文件（Google Ads 见 `plugins/traffic/google-ads/使用方法.md`）。上传成功后账本 `conversions.uploaded_at` 记时间；api 路自动，manual 路由主干在下一轮按 outbox 文件存在与否记。
