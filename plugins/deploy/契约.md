# 部署目标插件契约

::STATE{@PLUGIN_KIND, kind:deploy, first:cloudflare, what:"落地位：用户自有域名上的落地页、/go 中转（铸 token 存映射 302 出站）、/export 拉回，一把钥匙建全部"}

## 交钥匙

用户做的只有一件事：把这家云的钥匙放进环境变量。域名在不在账号里、DNS、存储、密钥、页面、中转，全部由 setup 一次建好，跑第二遍不多建。凡是要用户去控制台点东西的步骤，都是这个插件的缺陷。

## 动作

### setup

输入：`--host <自有域名下的主机名>`、钥匙（环境变量）。
输出：`{plan, steps, health, deploy_json, applied}`；写 `data/deploy.json`（host、base_url、export_url、export_key、存储 id），主干从这里读中转在哪。
`--teardown` 拆干净（测试收尾用）。

### publish

输入：`--page <html> --slug <slug>`，或 `--site --site-name --contact`（隐私与条款页），或 `--offers <json>`（offer_ref → 联盟链接与 sub-id 参数名，合并不覆盖）。
输出：`{pushed:[url], offers_total}`。只是存储写入，不重新部署。

### status

输入：无，或 `--roundtrip --offer <offer_ref> [--slug <slug>]`。
输出：`{health, roundtrip:{steps:[page, go, export], ok, token}}`。真点一次：页面 200、/go 302 带 sid、/export 里能找到这个 token。

::RULE{落地位必须在用户自有域名下⇒不用任何共享域名}
::RULE{映射导出接口必须带用户自己的密钥⇒主干ledger/subid.py pull拉回本地}
::RULE{setup默认dry_run⇒只有--apply才真建}
::RULE{只建只改自己建的东西⇒账号里别的Worker_DNS_存储一律不碰}

## manifest 必填

```json
{ "kind": "deploy", "actions": { "setup": "setup.py", "publish": "publish.py", "status": "status.py" } }
```
