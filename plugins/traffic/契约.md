# 流量平台插件契约

::STATE{@PLUGIN_KIND, kind:traffic, first:google-ads, later:"bing meta tiktok"}

一个流量平台插件把主干的平台无关规格翻译成自家后台的字段，把自家报表翻译回主干的标准报表，把主干的离线转化文件翻译成自家的上传格式。四个动作，缺一不可。

## 动作

### spec：生成投放规格

输入：offer 引用、落地页 URL、关键词列表（来自主干或关键词插件）、SOUL 参数（硬限）。
输出：`schemas/traffic-spec.schema.json` 形状的 JSON。

::RULE{spec输出必须通过schema校验且逐条满足hard_limits⇒否则退出码1并列出违反项}
::RULE{match只许phrase或exact|search_partners与display必为false|presence必为living_in|bidding必为manual_cpc}
::RULE{final_url必须在用户自有域名下⇒不许直投联盟链接}

### deploy：部署

输入：spec JSON。
输出：部署结果 JSON `{campaign_id?, adgroup_ids?, applied, mode}`；`mode` 为 `manual` 或 `api`。

两条路，都要在使用方法里写清：
第一条 `manual`，Agent 在用户自己的浏览器里操作平台后台，按 spec 逐项填，填完导出自证 JSON（同 spec 形状）；主干记 `evidence:manual_check`。
第二条 `api`，用户自己持有该平台的 API 凭据时走 API。凭据全在用户环境变量里。`deploy` 动作的脚本要同时接 `--spec`（建）和 `--actions`（执行主干判断出的动作），默认 dry-run，支持 `--validate-only`，中途失败要回滚。

::RULE{新账号首次deploy⇒daily_budget不超过SOUL的first_day_budget 不一天内反复改动}
::RULE{deploy默认dry_run⇒打印将要建的每一项 只有--apply才真建}

### report：拉报表

输入：日期窗口、账号。
输出：`schemas/traffic-report.schema.json` 形状的 JSON，`source` 标明 `csv_export` 还是 `api`。

::RULE{没有API凭据⇒Agent从后台导出CSV 插件用report_import把CSV翻译成标准报表 主干只认标准报表}
::RULE{报表里出现disapproved或policy⇒原样带出 主干的anomaly节点会看}

### convert：回传转化

输入：主干 `core/ledger/reconcile.py` 生成的平台无关转化行（gclid、转化名、时间、金额、币种）。
输出：该平台后台能直接上传的文件（Google Ads 是离线转化 CSV），以及有 API 时的上传结果。

::RULE{转化时间必须晚于点击时间且在平台允许的回传窗口内⇒超窗的行单独列出不上传}
::RULE{拒付⇒生成对应的负向或调整行 用平台支持的调整方式 不伪造}

## 平台变动的处理

平台 API 会变（Google：developer token 2026-09-09 起废弃、权限级别归 Google Cloud 项目，离线转化迁 Data Manager API，版本每季度强制升级，新 OAuth refresh token 要求 passkey）。`manual` 路不受影响，这是它作为默认路的原因；`api` 路的变动只改该插件目录，主干不动。

## manifest 必填

```json
{ "kind": "traffic", "actions": { "spec": "spec.py", "deploy": "manual", "report": "report_import.py", "convert": "convert_export.py" } }
```
