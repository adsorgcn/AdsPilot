# 使用方法：Google Ads 流量插件

::STATE{@PLUGIN, id:traffic/google-ads, contract:plugins/traffic/契约.md, default_path:manual, api_path:"用户自有凭据 可选"}
::OBJECTIVE{id:ga|owner:user|trust:untrusted|version:1|status:active}
  target: 在用户自己的 Google Ads 账号里，按主干给的规格建搜索系列，每天把报表带回主干，把对账后的转化灌回后台
  ACCEPT: spec 过校验 AND 系列状态为已启用 AND 连续 3 天报表进了主干 AND 首批转化文件上传成功
  NON_GOALS: 展示网络、搜索合作伙伴、自动出价、任何非本人账号

## 账号前提（本人做）

[STEP:0|账号|by:human]
本人真实身份注册的 Google Ads 账号，付款方式本人，账号所在国与付款地一致。平台要身份或付款验证就照实做。这一步 Agent 不代做。

## 四个动作

[STEP:1|spec 生成投放规格|by:agent]
写一个 brief（照 `tests/fixtures/brief.example.json`），跑：

```bash
python3 plugins/traffic/google-ads/spec.py --brief data/inbox/brief.json --out runs/spec.json
```

退出码 1 就按打印的违反项改 brief，不改硬限。硬限来自 SOUL 与 `config.caps`：匹配只许词组或精确；Search Partners 与 Display 关；地理只投「位于」目标市场的人；Manual CPC；新账号首日预算不超过 `first_day_budget`；Final URL 必须是自有域名的落地页。

[STEP:2a|deploy 部署（api 路，有自有凭据时默认）|by:agent]

```bash
python3 plugins/traffic/google-ads/deploy_api.py --spec runs/spec.json                 # dry-run 只列步骤
python3 plugins/traffic/google-ads/deploy_api.py --spec runs/spec.json --validate-only # Google 只校验预算与系列
python3 plugins/traffic/google-ads/deploy_api.py --spec runs/spec.json --apply         # 真建，建好即 PAUSED
python3 plugins/traffic/google-ads/deploy_api.py --spec runs/spec.json --apply --enable # 建好直接启用
```

顺序是预算 → 系列 → 地理与语言与否定词 → 广告组 → 关键词 → 响应式搜索广告；中途失败自动把已建的删掉，不留半成品。系列默认建成 PAUSED，让本人在后台看一眼再开，或者带 `--enable`。日常循环里的动作（暂停、降价、加减预算、暂停词、加否定词）由主干自动喂给 `deploy_api.py --actions`，出价按各币种的计费单位取整。2026-09-25 在真实账号实测过一遍：建、改、删全通。

[STEP:2b|deploy 部署（manual 路，没有 api 凭据时）|by:agent_in_users_browser]
在用户自己的浏览器里打开 Google Ads 后台，按 `runs/spec.json` 逐项填：

`[RUN:@BROWSER|whr=ads.google.com]`
新建广告系列 → 目标选「没有目标的指导」或「网站流量」→ 类型「搜索」→ 关闭「包括 Google 搜索合作伙伴」与「包括 Google 展示广告网络」→ 地理位置填 spec.campaign.geo.countries，选项选「位于或经常位于目标位置的用户」（presence:living_in）→ 语言 spec.campaign.language → 出价「手动每次点击费用」，最高 CPC spec.campaign.bidding.max_cpc → 每日预算 spec.campaign.daily_budget → 广告组名与关键字按 spec.adgroups（词组用引号，精确用方括号）→ 响应式搜索广告填 headlines 与 descriptions，最终到达网址 spec.adgroups[].final_url → 跟踪模板填 spec.campaign.tracking_template → 否定关键字填 spec.campaign.negatives → 保存并启用。

做完导出自证 JSON（同 spec 形状，从后台读回来填），存 `runs/<id>/deployed.json`，教练要看就贴这个。主干记 `evidence:manual_check`。

::RULE{后台提示政策问题或要求验证⇒停 报告needs_human 不改文案硬闯 不换账号}
::RULE{一天内不反复改动同一系列⇒新账号尤其}

[STEP:3|report 拉报表|by:agent]
manual 路：后台「报告」→ 预定义报告「关键字」→ 按天分段 → 时间范围最近 30 天 → 下载 CSV，存到 `config.traffic.report_csv`（默认 `data/inbox/google-ads-report.csv`）。主干每轮跑：

```bash
python3 plugins/traffic/google-ads/report_import.py --csv data/inbox/google-ads-report.csv --out runs/<id>/traffic-report.json
```

api 路：用户自己在 Google Cloud 项目里建了 OAuth 桌面客户端、拿到 refresh token 时，环境变量填齐，`config.traffic.report_source` 改 `api`，主干自动跑 `report_api.py`。凭据只在环境变量里。

[STEP:4|convert 回传转化|by:agent]
主干对账后产出 `runs/<id>/conversions.json`，本插件翻译成后台上传文件：

```bash
python3 plugins/traffic/google-ads/convert_export.py --conversions runs/<id>/conversions.json --out data/outbox/conversions-<id>.csv --timezone Asia/Tokyo
```

上传：后台「目标」→「转化」→「上传」→ 来源「从文件上传」→ 选 `conversions-<id>.csv` →「预览」无错后「应用」。转化操作名要事先在后台建好（`config.traffic.conversion_name`，来源「导入」，类别「购买」，计入「每一次」，归因「数据驱动」或「最终点击」）。有 `.adjustments.csv` 就再走一次「转化调整」上传（拒付 RETRACTION）。

api 路：

```bash
python3 plugins/traffic/google-ads/convert_api.py --conversions runs/<id>/conversions.json --timezone Asia/Tokyo --apply
```

它会自动建「点击上传」类型的转化操作（没有就建），再上传。**注意 Google 2026-09 的口径（实测）**：新接入的账号不能再用 Google Ads API 的 `uploadClickConversions`，必须走 Data Manager API，而 Data Manager 需要 OAuth 多一个 scope `https://www.googleapis.com/auth/datamanager`。用户拿 refresh token 时要把这个 scope 一起授权；没有的话脚本退出码 2 报 `needs_reauth`，本人重新授权一次换新 token。拒付撤回仍走 Google Ads API 的转化调整。没 api 凭据就用上面的 CSV 路，形状一样。

::RULE{上传预览报错⇒把错误原样贴进runs/<id>/run.log 不改gclid 不改时间}
::RULE{转化时间距点击超过90天的行⇒不上传 已在conversions.json的out_of_window里}

## 每日无人值守下这块怎么跑

api 路（`config.traffic.deploy_mode` 为 `api`，凭据齐）：主干每轮自动拉报表、自动执行 M1 与 M2 的动作、自动上传转化，Agent 不用碰后台；只剩「本人」的三处。凭据缺一样就自动退回 manual 路。

manual 路里 Agent 每天做两件事：导出关键字报表到 inbox；把 `runs/<id>/actions-todo.json` 里 M1、M2 的动作（暂停、降价、加预算）在后台做掉，然后 `python3 core/loop/daily.py --ack <run_id>`。其余全是主干脚本。

## Google 的变动（2026 到 2027）

developer token 2026-09-09 起废弃，API 权限级别（Test、Basic、Standard）由生成 OAuth 凭据的 Google Cloud 项目决定，旧 token 的级别已按最近 90 天调用日志自动转到对应项目；离线转化导入迁 Data Manager API；API 版本每三到四个月强制升级（改 `GOOGLE_ADS_API_VERSION`，当前默认 v25）；新 OAuth refresh token 要 passkey。manual 路不受影响，所以它是默认路。
