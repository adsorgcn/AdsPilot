# 使用方法：CJ 联盟插件

::STATE{@PLUGIN, id:affiliate/cj, contract:plugins/affiliate/契约.md, sub_id_param:sid, readback:shopperId}
::OBJECTIVE{id:cj|owner:user|trust:untrusted|version:1|status:active}
  target: 用本人 CJ 发布者账号拉 offer 数据、生成带 token 的链接、每天把佣金明细与拒付带回主干
  ACCEPT: 四个动作各跑通一次 AND 佣金明细里 shopperId 回读到主干发的 token
  NON_GOALS: 选 offer（那是主干 offer.select 节点的事）、任何非本人账号

## 账号前提（本人做）

[STEP:0|发布者账号|by:human]
本人真实身份注册 CJ 发布者账号，填本人税务信息（非美国人 W-8BEN），网站填自己的域名并通过验证。审核不过或所在国不接受，这条线判停，不换身份不注册新号。

[STEP:0.1|API 凭据|by:human]
CJ 开发者门户（developers.cj.com，Personal Access Tokens）生成一个 token，放环境变量 `CJ_ACCESS_TOKEN`；发布者 CID（7 位，后台右上角账户下拉里）放 `CJ_PUBLISHER_ID`；推广媒介 ID（9 位，accounts.cj.com/promotional-properties 里那一栏「媒介 ID」）放 `CJ_WEBSITE_ID`，Link Search 认的是它不是 CID，传错回 `Website id specified does not match your account`。仓库与日志里不出现值。

## 四个动作

[STEP:1|offers 拉 offer 数据|by:agent]

```bash
python3 plugins/affiliate/cj/offers.py --out runs/<id>/offers.json
python3 plugins/affiliate/cj/offers.py --advertiser-ids 100001,100002 --out runs/<id>/offers.json
```

API 给 EPC（7 天与 3 个月，每百次点击）、网络排名、品类、佣金条款，每页 100 家自动翻页；加 `--with-links` 每家再取一条 Text Link 的点击链接进 `click_url`（需要 `CJ_WEBSITE_ID`）。**PPC 与品牌词竞价政策 API 不给**：Agent 在 CJ 后台打开该商家的 Program Terms 读一遍，把核对过的值写进 `data/inbox/cj-offer-policy.json`（按 advertiser_id 键：`ppc_allowed`、`brand_bidding_allowed`、`cookie_days`、`lock_days`、`allowed_traffic`、`reversal_rate`），再跑一次 offers。没核对就是 null，主干按不允许处理。

::RULE{Program_Terms写明不许PPC或不许品牌词⇒ppc_allowed或brand_bidding_allowed填false 不投}

[STEP:2|link 生成带 token 的链接|by:agent]
从 CJ 后台或 Link Search 拿到点击链接（click URL），主干 `core/ledger/subid.py mint` 发 token，本动作把 `sid=<token>` 装进去：

```bash
python3 plugins/affiliate/cj/link.py --base "<click_url>" --token <token>
```

日常里这一步由自有域名的中转（`plugins/deploy/cloudflare-worker`）在每次点击时自动做：`/go` 铸 token、存映射、302 到带 sid 的链接。

[STEP:3|commissions 拉佣金明细|by:agent]

```bash
python3 plugins/affiliate/cj/commissions.py --days 7 --out runs/<id>/commissions.json
```

回读字段用 `shopperId`（`sid` 字段官方 schema 已标废弃）。2026-09-25 真凭据实测口径：GraphQL 里集合字段叫 `records`（不是文档旧例里的 payloads）；单次查询的时间窗不能超过 31 天，脚本按 30 天一段自动切；一段内分页看 `payloadComplete` 与 `maxCommissionId`，自动翻页。没有 API 时的退路：后台 Reports → Commission Detail 导出 CSV，`--csv <file>`。主干每轮自动跑这一步，退出码 4（凭据缺失）会自动退到 `config.affiliate.commissions_json`。

[STEP:4|chargebacks 拒付解析|by:agent]

```bash
python3 plugins/affiliate/cj/chargebacks.py --commissions runs/<id>/commissions.json --out runs/<id>/chargebacks.json
```

纠正与拒付在 CJ 里是 `original:false` 的负额记录，`originalActionId` 指向原事件。关联不上的行在 `unlinked` 里，主干不为它们做负转化。

## 实测记录

2026-09-25 用真实发布者账号只读跑通四个动作：offers 187 家 joined 商家分页取齐（EPC、排名、品类、佣金条款），`--with-links` 批量取到点击链接；link 在真实 `dpbolvw.net` 点击链接上装 `sid` 且保留原参数；commissions 90 天切三段查询通过（该账号窗口内 0 笔）；chargebacks 与 schema 校验通过。仍待核对：`sid` 的确切长度上限（本插件按 32 位 token 设计）；CJ 对完整集成是否要求技术集成工程师配合。
