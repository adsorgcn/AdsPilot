# 判断插件契约（感知层提供者）

::STATE{@PLUGIN_KIND, kind:judgment, first:"llm jev soul-api", local_fallback:"core/judge 本地规则 永远在"}

iLang v5 把判断分两层：感知层把场景变成 11 维向量，决策层把向量变成模式 M1 到 M8。**插件只做感知层。** 决策层是主干里按 f_v5 写死的函数，可审计，任何提供者报的模式只作对照，不作数。

## 动作

### judge

输入：`schemas/judgment.schema.json` 的 request（node、state、choices、caps、evidence、soul）从 stdin 进；命令行是 `--config <config.judgment 的 JSON> --soul <这次用的 SOUL 文件路径>`，相对路径按仓库根解析。
输出：至少 `{v, reason, choice, conf}` 或（无向量的决策提供者）`{choice, conf, reason}`；`v` 是 11 维向量，两位小数，固定顺序 `int,cap,csq,rel,cer,aut,rev,evd,sov,ine,ext`；`choice` 是 choices 里的一个 id；`conf` 是诊断用置信度，不改变模式。可选 `distribution`（各选项概率）。

主干 `core/judge/judge.py` 在调用任何提供者之前先执行 `scrub_judgment_payload()`，集中剥离凭据、gclid/gbraid/wbraid 原文与原始 IP 列表（保留 `gclid_all_valid` 与枚举 `gclid_kind` 以及聚合风险数 `ip_flagged`/`ip_risk_ratio`）。拿到响应后主干自己算 `mode_local = f_v5(v)`，再套 SOUL 的 `::BOUNDARY`，最后决定动不动。

配置 `judgment.provider` 可指定主提供者，或额外配 `judgment.provider_chain`（有序回退列表，逐个尝试直到第一个成功，全失败再退本地规则 `local`）。插件名必须在 `plugins/judgment/<name>/manifest.json` 登记，禁止以 `_` 开头或含路径穿越字符。

::RULE{主干调用带--soul <path>⇒提供者用这个SOUL的规则 不许写死默认SOUL}
::RULE{提供者超时或失败⇒按provider_chain继续或退回本地规则 记fallback:true 循环不停}
::RULE{提供者输出的向量任一维缺失或越界⇒按STEP-0视为解析失败 模式M5 退回本地规则}
::RULE{提供者给的mode与本地f_v5不一致⇒以本地为准 差异写进日志与本轮报告}
::RULE{cer<0.30或evd<0.25⇒模式必为M5 除非命中生存边界为M8|这是v5冻结的弃权规则 不许绕}

## 三个首发提供者

`llm`：任何 OpenAI 兼容的聊天接口，公益期推荐便宜模型（DeepSeek 一类）。提示词让模型只输出一个 `::JUDGE{v5.0}` 块加一行 `CHOICE:<id>`，主干用正典的正则解析，解析失败即 M5 并可触发回退。

`jev`：TypeSafe AI 的决策模型，选项不超过 255 个，延迟几十到几百毫秒。支持 `/v1/systemone`（11 维 rubric 概率加权期望向量 + `choice` 分布，一次出齐 `v` 与 `choice`）及兼容早期 `/decide` 端点（只出 `choice` 与 `distribution`，向量由主干按本地规则补全）。模式仍按 `f_v5`。

`soul-api`：托管的判断服务（`POST <endpoint>/v1/judge`），公益期免费。同时支持正典 `v1` 请求/响应形状（`soul/soul-api.md`）与 `ilang-judge` `/v1/judge` 方言（`vector` + `probabilities` + `class5_key`）。

## 延迟与预算

::RULE{单次判断超8秒⇒放弃该提供者 继续回退或退回本地规则}

## 扩展与评测

新增提供者复制 `plugins/judgment/_template/` 到 `plugins/judgment/<name>/` 并通过 `validate.py --manifests` 与 `core/agent/interfaces.py --generate`。上线前用 `python3 core/judge/eval_provider.py --provider <name> --apply` 对照 `tests/fixtures/judge-benchmark.json` 跑一次 L2 基准门槛检查。
